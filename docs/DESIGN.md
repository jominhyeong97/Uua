## Problem Statement

LLM 세션은 기억이 없다. 새 창을 켜면 직전 작업 맥락이 사라진다. 지금 나(조민형)는 이걸
`handoff` 문서를 직접 써두고 새 세션에서 "xxx.handoff 읽어줘"로 잇는 식으로 *수동으로* 해결하고 있다.
이건 매번 맥락을 다시 만들고, 어떤 handoff가 최신인지 헷갈리고, 예전 결정이 어디 적혔는지 못 찾는 고통이다.

mnemo는 이 수동 작업을 백엔드 서비스로 대체한다. 작업 내용을 저장해두면, 새 세션/질문 시
**뜻으로 검색해 지금 필요한 맥락만** 골라 토큰 예산 안에서 묶어 돌려준다.

## What Makes This Cool (차별점)

"제2의 뇌 Q&A"(NotebookLM·Notion AI·Mem 등 레드오션)가 아니다. 차별점은 UI가 아니라 **메모리 엔진 내부**와
**에이전트 네이티브(MCP) 제공**에 있다. 2026년 가장 뜨거운 백엔드 카테고리(Mem0·Letta/MemGPT·Zep)와 같은 결.

- "세션 요약을 파일로 저장"(약한 버전, 그냥 래퍼)이 **아니다.**
- 뜻 기반 검색 + 최신성 랭킹 + **토큰 예산에 맞춘 컨텍스트 팩 조립** + **MCP 서버로 에이전트가 직접 호출**이 핵심.
- 면접 한 줄: *"AI 에이전트용 메모리 백엔드를 만들었다. 무엇을·언제 꺼낼지 결정해 토큰 예산에 맞춘 컨텍스트 팩을 조립하고 MCP로 제공한다."*

## 용어 사전 (주니어 친화 — 이 프로젝트로 배울 것들)

| 용어 | 쉬운 뜻 |
|------|---------|
| 임베딩(embedding) | 글을 숫자 목록(벡터)으로 바꾼 것. 뜻이 비슷하면 숫자도 비슷. Gemini가 만들어 줌. |
| 벡터검색 / top-K | 질문도 숫자로 바꿔, 저장된 것 중 *뜻이 가장 가까운 K개*를 고르는 것. pgvector가 DB에서 계산. |
| 컨텍스트 팩 | 고른 메모리 조각들을 토큰 한도 안에서 추려 묶은 묶음. |
| 토큰(token) | LLM이 글을 세는 단위. 한도 넘으면 잘리거나 비싸짐. |
| MCP | Model Context Protocol. Claude/Gemini 같은 에이전트가 외부 도구·데이터를 호출하는 표준. mnemo를 MCP 서버로 만들면 에이전트가 직접 메모리를 가져감. |
| RAG | Retrieval-Augmented Generation. "검색해서 찾은 내용을 LLM 답변에 넣는" 방식. mnemo의 읽기 경로가 이것. |

## Constraints

- **1인 + 주니어**: 따라 만들 수 있는 범위. 연구급 난제(자동 사실추출·모순해소)는 v2로 미룸.
- **무료 티어 고정**: Gemini 무료 임베딩/생성, 결제계정 미연결로 과금 구조적 차단. 무료 호스팅.
- **구직 타임라인**: 빨리 데모 가능한 상태가 중요. 좁고 깊게.
- 스택: Spring Boot(Java 21, Gradle) · Spring Data JPA + **네이티브 SQL**(벡터검색) · **Postgres + pgvector**(dev는 docker-compose, `pgvector/pgvector` 이미지) · `EmbeddingClient`/`LlmClient` 추상화 · Spring Security(단순 토큰/단일사용자).
- **임베딩 모델 고정**: Gemini `text-embedding-004`, **768차원** → pgvector 컬럼은 `vector(768)`로 선언(차원 틀리면 스키마 마이그레이션 필요).
- **무료티어 RPM 제약**: Gemini 무료 임베딩은 분당 호출수 제한이 낮음 → 내 ingest가 청크 수십 개를 한 번에 임베딩하면 *내가 먼저* 한도에 부딪힘. ingest는 순차+딜레이(또는 batch embed)로 스로틀.
- **호스팅 주의**: Railway/Render 무료티어가 pgvector 확장을 지원하는지 1단계 전에 확인. (Render 무료 Postgres는 90일 만료, 무료 웹서비스는 슬립.)

## Premises (확정 — 사용자 전원 동의)

1. 진짜 문제 = stateless LLM 세션 간 맥락 운반. 이미 수동 handoff로 매일 겪는 실재 고통.
2. 차별점은 UI가 아니라 메모리 엔진 내부 + MCP 제공. 자동 핸드오프는 데모 표면일 뿐.
3. 1차 사용자 = 본인(+본인 에이전트). 성공 = ⓐ매일 실사용 ⓑ묵직한 백엔드 면접 스토리. 대중시장 아님.
4. 배포/유통 = 자가호스팅 웹서비스 + MCP 서버, 무료티어 배포 + 데모.
5. 스택 = Spring Boot/Java 21 + Postgres+pgvector + Gemini 임베딩/무료티어 + LlmClient 추상화.
6. v1은 규칙기반 추출 + 최신성 우선 해소로 단순하게. 고도화(LLM 추출·모순감지)는 v2.

## Cross-Model Perspective

(이번 세션에서는 별도 2차 의견 cold-read를 돌리지 않음. 단, 직전에 같은 주제로 독립 엔지니어/전략 서브에이전트
리뷰를 2회 수행했고 그 결론 — "좁고·깊고·배포되고·측정된 하나가 넓고 얕은 셋을 이긴다", "비용/남용 방어는
말이 아니라 숫자로 증명하라" — 을 본 설계에 반영함.)

## Approaches Considered

### Approach A: Thin Slice → B로 확장  ★선택
메모리 아이템(텍스트 청크)을 project/session 태그와 함께 Gemini 임베딩→pgvector 저장. 읽기=쿼리/작업 주면
의미검색+최신성 부스트로 top-K → 토큰버짓 컨텍스트 팩 조립(출처 인용). 자동 핸드오프=세션 요약 인입 엔드포인트.
REST + MCP. 충돌해소=검색 랭킹에서 최신 우선. Effort S/M, Risk Low.

### Approach B: Full Memory Engine
LLM 기반 타입드 메모리 추출(fact/decision/entity/todo) + dedup + 모순감지 + supersedes 체인 + 하이브리드 검색
+ 관측성 대시보드. Effort L/XL, Risk High. → v1엔 과함, A의 확장 목표로.

### Approach C: Event-Sourced Memory
작업을 append-only 이벤트 로그로 적재, 메모리는 projection(CQRS). Effort M/L, Risk Med. → 아키텍처 스토리는
강하나 오버엔지니어링·실사용 거리 리스크. A 출시 후 선택적 도입.

## Recommended Approach

**A를 v1로 출시하되, B의 조각(타입드 메모리·모순감지)이 끼워질 수 있게 인터페이스를 미리 갈라둔다.**
구직 타임라인엔 빨리 실사용+데모 확보가 우선. A로 "내가 매일 쓰는 + 배포된 + 측정된" 상태를 만든 뒤,
모순해소·이벤트소싱을 "확장 스토리"로 단계 추가.

## v1 핵심 동작 (A)

1. **쓰기**: `POST /api/memories` (text, project, session, tags) → Gemini 임베딩 생성 → pgvector에 저장(provenance: 출처·시각·모델·토큰수 기록). **쓰기는 원자적**: 임베딩 실패 시 행을 저장하지 않고 503 반환(아래 실패경로).
2. **자동 핸드오프 인입**: `POST /api/sessions/{id}/ingest` (세션 텍스트 덩어리) → 고정창 청크 분할 → 각 청크 임베딩(스로틀) 저장. **v1은 LLM 요약 없이 원문 청크만 저장**(요약은 v2).
3. **읽기(컨텍스트 팩)**: `POST /api/context` (query 또는 project/task, maxTokens) → 질문 임베딩 → pgvector top-K(의미) + 최신성 부스트 점수 → 토큰 예산 안에서 그리디로 추려 **컨텍스트 팩**(인용 포함) 반환.
4. **비용/남용 방어(숫자로 증명)**: 입력 길이 가드(임베딩 호출 *전*), 임베딩 레이트리밋, 일일 상한+킬스위치, `UsageLog` 테이블 → **사용량 요약 JSON 엔드포인트**(`GET /api/usage/summary`) + 선택적 정적 HTML 표. (대시보드 풀 프론트엔드는 만들지 않음 — 백엔드 도구.)
5. **미니 평가셋(측정 스토리)**: 손으로 만든 정답지(아래 Assignment) 기반 — "쿼리 X에 대해 mnemo top-K가 내가 손으로 고를 청크를 포함했는가"(recall@K). v1 산출물.
6. **MCP 서버**: 위 읽기 경로를 감싸는 **얇은 stdio MCP 래퍼**(`recall_context` 도구) → 내 Claude Code/Gemini가 세션 시작 시 직접 호출. 새 비즈니스 로직 없음(기존 `/api/context` 로직 재사용, ~1일). **공개 REST 배포와 로컬 MCP는 별개 런타임**(아래 인증).

## v1 구체 스펙 (알고리즘·계약 — 주니어가 바로 구현 가능하게)

**청킹(chunking):** 고정 ~500토큰 창, 오버랩 없음. 토큰은 정확 토크나이저 대신 `대략 글자수/4`로 근사.

**점수(recency-boosted scoring):**
```
finalScore = cosineSim + w * exp(-ageInDays / τ)      # w=0.1, τ=30 (시작값, 실사용하며 튜닝)
```
cosineSim은 pgvector 코사인 거리(`<=>`)를 유사도로 환산.

**컨텍스트 팩 조립(greedy token budget):**
```
1) finalScore 내림차순 정렬
2) 토큰합 < maxTokens 인 동안 위에서부터 청크 추가
3) 예산 초과 직전에 멈춤 → 추가된 청크들을 인용과 함께 묶어 반환
```

**`/api/context` 응답 예시:**
```json
{
  "pack": "다음은 관련 메모리입니다:\n[1] ...\n[2] ...",
  "items": [
    {"text": "ORBIT 워크스페이스 Kafka 보상 트랜잭션 결정...", "source": "session:abc", "createdAt": "2026-05-20T09:00:00Z", "score": 0.81},
    {"text": "N+1 Fetch Join 전략 메모...", "source": "memory:42", "createdAt": "2026-05-18T14:00:00Z", "score": 0.74}
  ],
  "usedTokens": 480,
  "maxTokens": 1000
}
```

**임베딩 실패 경로:** 429/타임아웃 → 503 반환, 행 저장 안 함(원자성). v1엔 재시도 큐 없음(즉시 503, 사용자가 재요청).

**입력 검증:** 빈/공백 텍스트 거부(400), 요청당 최대 길이 초과 거부(413), ingest당 청크 수 상한.

**MCP 인증/전송:** v1은 **로컬 stdio**(네트워크 인증 불필요, 내 머신에서 dogfood). 공개 REST는 단순 API 토큰 1개. 둘은 다른 표면.

**벡터검색 = 네이티브 SQL:** Spring Data JPA 파생쿼리로 벡터검색 불가. `@Query(nativeQuery=true)` 또는 `JdbcTemplate`로 `ORDER BY embedding <=> :q LIMIT :k`. 임베딩 컬럼은 커스텀 타입 매핑 또는 네이티브로 읽고/쓰기.

## 데이터 모델 (초안)

- `MemoryItem` — id, projectKey, sessionKey, text, embedding `vector(768)`, source, model, tokenCount, createdAt, supersedesId(nullable, **v1 미사용** — B 대비 자리만).
- `IngestEvent` — 원본 인입 추적(어떤 세션 텍스트가 어떤 청크로 갈렸나).
- `UsageLog` — userId, endpoint, op(embed/generate), tokenCount, latencyMs, outcome, createdAt. (쿼터/사용량요약 단일 출처.)
- 검증: text `@NotBlank` + 최소/최대 길이.

## 추상화 (면접 어필 + 교체 가능)

- `EmbeddingClient.embed(text) → float[768]` — Gemini `text-embedding-004` 구현. 나중에 로컬 모델 교체 가능.
- `LlmClient.complete(req) → resp` — **v1 미사용**(v2 세션 요약용 자리). v1은 임베딩 한 종류 API만 의존.
- 토큰캡·타임아웃·429 처리 매트릭스를 구현체에서 중앙 관리(`@ConfigurationProperties`).
